# Jellio for macOS

Electron shell for Jellio: one window onto the user's Jellyfin server at
`/web/`, where the Jellio plugin's own frontend runs. Offline support is
the plugin's (its service worker and `runtime/offline.js`); this app adds
only what a browser tab can't: a native menu, Dock badge, keeping downloads
alive with the window closed, and a setup/offline page of its own.

## Relationship to Jellio-Plugin

Anything a screen needs belongs in `NoahSKipp/Jellio-Plugin`, not here.
The app reads the plugin's IndexedDB (`jellio-offline`, store `downloads`)
for the download count, so a change to that schema is a change here too.

## Working rules

Same hard rules as `NoahSKipp/Jellio-Plugin`, unchanged:

- Every commit is GPG signed with key `9D82CFAE019B44EE`.
- No `Co-Authored-By` trailers. Ever.

- Branch names describe the feature being worked on.
- Never include the word `claude`.

- Comments are sparse. Only for genuinely non obvious blocks, written as a
  short note to self, not documentation prose.
- No banner comments, no section dividers, no restating what the line does.

### Writing

- No em dashes anywhere. Not in code, comments, docs, commit messages,
  config, UI strings or release notes.

## Layout

```
src/main.js       window, menu, navigation rules, server setup, quit guard
src/preload.js    jellioNative bridge, download count from IndexedDB
src/config.js     settings JSON in userData
src/updates.js    GitHub latest-release check
src/pages/        setup and offline pages
scripts/          ad hoc signing (afterPack)
build/icon.png    app icon, rendered from the plugin's jellio mark
```

## Platform

Apple Silicon only (`arm64`), macOS 12 and later; Sequoia must keep
working. No Developer ID: builds are signed ad hoc and not notarized, so
there is no Squirrel auto-update, only a check that links to the release.

## Release automation

Mirrors Jellio-Plugin: `release.yml` (workflow_dispatch) runs `make
release`, which bumps `package.json` with git-cliff, commits, pushes and
creates the GitHub release. `publish.yml` then builds the dmg and zip on a
macOS runner and attaches them with checksums. Needs the `RELEASE_TOKEN`
repo secret (a PAT with `contents:write`; `GITHUB_TOKEN` can't trigger
`publish.yml`).
